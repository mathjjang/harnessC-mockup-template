# 검수 접수 — 테스트 서버에서 발견한 것의 창구

> 왜 여기인가: 기획·검수자가 보는 저장소가 접수처다. **유형이 처리 경로를 정한다** — 오류는 개발 저장소가 가져가 고치고, 기획수정은 이 저장소에서 목업·정책을 고친 뒤 개발이 따라오고, 정책공백은 사람이 결정한다. 기획수정을 개발 경로로 보내지 않는 것이 핵심 장치다(에이전트가 기획 없이 화면·정책을 임의로 바꾸는 것을 구조로 차단). 도구 `node scripts/qa.mjs`.

## 1. 접수 — 검수자는 사실만 낸다

```bash
node scripts/qa.mjs new <slug> "<증상 한 줄>" --by "<이름>" [--screen <모듈>/<화면>] [--server <테스트 서버>] [--capture <캡처·로그>]…
```

`report.md`에 **무엇을 했나(재현 절차) · 무엇이 나왔나 · 되어야 할 모습 ★**을 채운다. 되어야 할 모습은 **보고자의 말 그대로** — 번역하면 정보가 준다. 캡처·로그는 원본 그대로 `intake/`. 심각도·유형·담당은 검수자가 정하지 않는다.

## 2. 분류 — 에이전트가, 근거를 남기며

판별 질문을 위에서부터 적용한다:

1. **확정 목업·policy.md에 이 상황의 답이 있나?** 없다 → `정책공백`
2. **답이 있는데 제품이 다르게 동작하나?** → `오류` (콘솔 에러·깨진 화면·저장 실패는 볼 것도 없이 오류)
3. **답대로 동작하는데 그 답을 바꾸고 싶나?** 화면 모습·배치 → `기획수정(UI)` · 동작 규칙·권한·데이터 → `기획수정(정책)`

```bash
node scripts/qa.mjs classify <ID> <유형> "<근거 — 캡처 속 URL·콘솔 경로·기획의 어느 절>" --by "<에이전트(모델)>"
```

- 확신이 없으면 `미정`으로 두고 검수자에게 화면 위치를 되묻는다. 틀린 분류로 발주하는 것보다 낫다. 틀렸으면 다시 classify.
- 복합 건(오류도 있고 바꾸고도 싶다)은 **건을 나눈다** — 처리 경로가 다르다.
- "불편하다·헷갈린다"는 기획에 정의가 있으면 기획수정(UI), 없으면 정책공백.

## 3. 유형별 경로

| 유형 | 어디서 누가 | 닫히는 조건 |
|---|---|---|
| `오류` | **개발 저장소**가 가져간다(`qa-intake.mjs pull`) → 고침 → 리뷰어(수정자와 다른 세션)가 `resolution.md`를 `verified`로 | 기획이 테스트 서버에서 확인 후 `close`. resolution이 resolved·verified가 아니면 닫히지 않는다 |
| `기획수정(UI)` | **이 저장소**: `confirm.mjs <화면> --reopen` → 고침 → `confirm`(rev+1) → `qa.mjs change <ID> "<모듈>/<화면> rev N"` → 개발이 재승격·재구현 | 반영 근거(change) 없이는 닫히지 않는다 |
| `기획수정(정책)` | **이 저장소**: `confirm.mjs <화면> --reopen` → policy.md 개정 → `confirm`(rev+1) → `qa.mjs change <ID> "<모듈>/<화면> rev N"` → 개발이 재승격·재구현 (정책도 지문 대상 — 화면만 잠그면 규칙이 rev 없이 바뀐다) | 같음 |
| `정책공백` | 사람 결정 → `qa.mjs decide <ID> "<결정>"` → 결정에 따라 다시 classify | 결정 없이는 닫히지 않는다 |

## 4. 닫기·재열림 — 사람만

```bash
node scripts/qa.mjs close <ID> --by "<이름>" "<확인 방법 — 테스트 서버에서 무엇을 봤나>"
node scripts/qa.mjs reopen <ID> "<여전히 재현되는 이유>"
```

- 닫기는 보고자(기획)의 확인 기록이다. 에이전트는 닫지 않는다. "재현 불가"로 닫지 않는다 — 검수자에게 관측을 되묻는다.
- `qa/INDEX.generated.md`(생성물)의 「사람 할 일」만 보면 된다: 분류 대기 · 결정 대기 · 확인 후 닫기.

## 경계

- 이 저장소의 `report.md`에 개발 저장소의 경로·기록 ID(`FDR-`·`docs/features/`…)를 쓰지 않는다 — 게이트가 거부한다. 개발 쪽 기록은 `resolution.md`(개발 소유)에만 있고, 이 저장소는 그 파일을 읽기만 한다.
- 에이전트가 작업 중 스스로 찾은 결함은 여기 오지 않는다(개발 저장소 자기 작업 단위로). 여기는 **사람이 써보다 발견한 것**의 접수처다.
